KB Intelligence: Pattern Emergence & Contradiction Detection

Higher-order reasoning over accumulated knowledge

1. From Storage to Intelligence

A memory system that only stores and retrieves is a database. Intelligence requires reasoning over stored knowledge: challenging claims, surfacing patterns, finding connections, and detecting contradictions. KB Intelligence provides these higher-order operations.

2. Challenge: Claim Verification

Given a claim ("The user uses Python"), the challenge operation checks it against existing knowledge. It finds supporting memories (those that mention Python or related terms) and contradicting memories (those that mention a different language without Python).

The algorithm uses keyword overlap: memories sharing ≥2 words with the claim are considered relevant. Among relevant memories, those with negation indicators ("not", "don't", "never") that differ from the claim's negation status are flagged as contradicting.

function challenge(claim) {
  const words = claim.toLowerCase().split(/\s+/).filter(w => w.length > 2);
  for (const memory of activeMemories) {
    const overlap = words.filter(w => memory.text.includes(w)).length;
    if (overlap >= 2) {
      const isNegation = memory.text.includes('not') || memory.text.includes("don't");
      const claimNegation = claim.includes('not') || claim.includes("don't");
      if (isNegation !== claimNegation) contradicting.push(memory);
      else supporting.push(memory);
    }
  }
  return { verdict: supporting.length > 0 ? 'supported' : contradicting.length > 0 ? 'contradicted' : 'insufficient' };
}

3. Emerge: Pattern Surfacing

The emerge operation finds patterns across the memory store by clustering memories along three dimensions:

  • By kind: Groups memories by their kind (fact, preference, decision, etc.). If 5+ facts exist, that's a pattern.
  • By slot: Groups memories by their slot (home_city, name, etc.). Multiple memories for the same slot indicate evolution or contradiction.
  • By subject: Groups memories by subject (user, Ponti Studios, etc.). A subject with 3+ memories has a rich knowledge profile.

Each pattern includes the memory IDs involved, enabling drill-down into the supporting evidence.

4. Connect: Topic Bridging

The connect operation finds how two topics are connected in the knowledge graph. Given "TypeScript" and "Edinburgh", it:

  1. Finds entities matching each topic
  2. Computes shortest paths between all pairs (BFS)
  3. Finds bridge entities (entities connected to both topics within 2 hops)

Bridge entities are the "glue" that connects disparate topics. For example, "Ponti Studios" might bridge "TypeScript" and "Edinburgh" if the user uses TypeScript at Ponti Studios in Edinburgh.

5. Contradictions: Detection

Contradictions are detected when two active memories share the same slot but have different value_text. For example:

  • Memory A: "The user lives in London" (slot: home_city)
  • Memory B: "The user lives in Edinburgh" (slot: home_city)

These are flagged as contradictions with severity based on confidence: high (both ≥0.8), medium (one ≥0.5), or low.

Contradictions are surfaced in the review queue for human resolution (confirm, dismiss, or edit).

6. Lint: Knowledge Base Health

The lint operation checks the knowledge base for quality issues:

  • Low confidence: Active memories with confidence < 0.5
  • Missing slots: Active memories without a slot (when 5+ exist)
  • Duplicates: Memories with identical value_text
  • Orphaned entities: Entities with no relationships
  • Deprecated pages: Wiki pages marked as deprecated

The health score is 1 - (issues * 0.1), capped at 0-1. Each issue reduces health by 10%.

7. Design Decisions

  • Keyword-based challenge: Uses keyword overlap instead of LLM calls. Faster and cheaper, but less nuanced than semantic comparison.
  • Slot-based contradictions: Only checks contradictions within the same slot. This is efficient but misses cross-slot contradictions (e.g., "lives in London" vs "workplace is in Edinburgh" when they should be the same city).
  • Simple lint checks: Rule-based checks, not LLM-based. Fast and deterministic, but might miss subtle quality issues.
  • Review queue integration: Contradictions are surfaced for human resolution rather than auto-resolved. This prevents the system from making incorrect decisions about conflicting information.

Trade-off: KB Intelligence uses rule-based heuristics instead of LLM reasoning. This is fast and free (no API calls) but less sophisticated than LLM-based analysis. For production use, the challenge and emerge operations could be enhanced with LLM calls for deeper semantic understanding.
