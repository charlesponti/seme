How It Works

The animation above demonstrates three key operations:

  1. Build Graph: Entities appear as nodes, relationships as edges. Each entity is typed (person, organization, place, tool, animal) and has source provenance.
  2. N-Hop Traversal: Starting from "Charles", the algorithm explores 2 hops outward, highlighting visited nodes and edges. This is how the system finds related context during retrieval.
  3. Shortest Path: BFS finds the shortest path between "Charles" and "Edinburgh" through the graph. The path is highlighted in blue.

The graph uses SQLite's recursive CTEs for traversal — no separate graph database needed. Recursive CTEs provide BFS/DFS traversal in pure SQL, keeping the system simple and single-file.
