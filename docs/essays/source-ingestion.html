Source Ingestion: Content Extraction & Chunking

How Seme ingests URLs, PDFs, YouTube videos, and text into the memory system

1. From External Content to Memory

Seme's memory system was designed for conversation turns. But users also have knowledge in external sources: documentation, articles, PDFs, YouTube videos. Source ingestion bridges this gap by extracting text from external sources and converting it into conversation turns that the extraction pipeline can process.

The key insight is that we don't need a separate extraction path. By converting external content into turns, the existing extraction pipeline handles it automatically. The only new concern is provenance: tracking where each memory came from.

2. Content Extraction

Each source type requires a different extraction strategy:

2.1 URLs

Fetch the HTML, strip script/style tags, remove HTML tags, decode entities, and normalize whitespace. The title is extracted from the <title> tag. This is a simple HTML-to-text conversion — not as sophisticated as Readability or similar algorithms, but sufficient for extracting factual content.

2.2 PDFs

Uses pdftotext -layout (from the poppler-utils package) to extract text with layout preservation. The layout flag maintains the visual structure (columns, tables) which helps the LLM understand the document structure.

2.3 YouTube

Uses yt-dlp to download auto-generated subtitles (VTT format), then strips VTT timestamps and HTML tags to get plain text. Falls back to a placeholder if transcripts are unavailable.

2.4 Plain Text

No extraction needed — the text is used as-is. This is useful for pasting notes, documentation, or any text content.

3. Chunking Algorithm

External content is often too long for a single LLM call. The chunking algorithm splits content into manageable pieces:

  1. Split content by paragraph boundaries (\n\n)
  2. Accumulate paragraphs into a chunk until it reaches ~2000 characters
  3. When a chunk is full, start a new one
  4. If no paragraph boundaries exist, fall back to character-based chunking
function chunkText(text, maxChunkSize) {
  const chunks = [];
  const paragraphs = text.split(/\n\n+/);
  let current = '';
  for (const para of paragraphs) {
    if (current.length + para.length > maxChunkSize && current.length > 0) {
      chunks.push(current.trim());
      current = para;
    } else {
      current += (current ? '\n\n' : '') + para;
    }
  }
  if (current.trim()) chunks.push(current.trim());
  return chunks;
}

Each chunk is wrapped with source provenance: [Source: Title (URL)] chunk text. This ensures the LLM knows the content comes from an external source and can attribute memories accordingly.

4. Turn Creation

Each chunk becomes a user turn in a new or existing session. The turn content includes the source prefix, so the extraction pipeline treats it as user-stated content. The extraction pipeline then processes these turns normally, extracting memories, entities, and relationships.

This means source ingestion reuses the entire existing pipeline — no new extraction logic needed. The only difference is the source provenance prefix.

5. Provenance Tracking

A sources table records metadata about each ingested source:

  • id: Unique source ID
  • title: Source title (from HTML title tag, filename, or user-provided)
  • url: Source URL (null for text/PDF)
  • source_type: url, pdf, youtube, text, file
  • content_length: Total characters extracted
  • created_at: Ingestion timestamp

This enables "where did this memory come from?" queries. A memory extracted from a URL will have the URL in its evidence quote, and the source record provides additional metadata.

6. Design Decisions

  • Reuse existing pipeline: Instead of building a separate extraction path for external content, we convert it to turns. This means source ingestion automatically benefits from all memory extraction improvements.
  • Paragraph-based chunking: Splitting on paragraph boundaries preserves semantic coherence. A fact that spans two sentences stays in the same chunk.
  • Source prefix: The [Source: ...] prefix tells the LLM the content is from an external source, which affects modality tagging (quoted vs. stated).
  • External tools: Uses pdftotext and yt-dlp instead of JavaScript libraries. This avoids adding heavy dependencies and leverages battle-tested tools.

Trade-off: The HTML-to-text conversion is naive (strips tags, decodes entities). It doesn't handle JavaScript-rendered content, complex layouts, or paywalled articles. For production use, a more sophisticated extraction tool (like Readability.js or Firecrawl) would be better.
