API-1

Record → End → Extract → Retrieve → Profile

The complete conversation lifecycle: from raw turns to structured memories, profile, and retrieval.

What This Tests

This is the core end-to-end flow. A user has a conversation, the system extracts memories from it, compiles a profile, and then retrieves relevant memories when asked a question.

How It Works

1

Record Turns

The client sends user and assistant messages to POST /sessions/:id/turns. Each turn is stored in the turns table with role, content, and timestamp. The system also creates or reuses an open episode for the session.

curl -X POST /sessions/s1/turns -d '{"role":"user","content":"I prefer dark mode."}'
2

End Session

When the conversation ends, POST /sessions/:id/end closes the episode and triggers the extraction pipeline asynchronously. The pipeline runs in the background.

curl -X POST /sessions/s1/end -d '{}'
3

Extract Memories

The extraction pipeline sends the conversation to the LLM with a structured prompt. The LLM identifies atomic claims (facts, preferences, decisions, etc.) and returns them as structured memories with subject, predicate, value_text, slot, and confidence.

// LLM extracts: "The user prefers dark mode for all editors."
{
  "kind": "preference",
  "slot": "theme",
  "value_text": "The user prefers dark mode for all editors."
}
4

Retrieve Context

When the user asks a question, POST /sessions/:id/retrieve searches memories using FTS5 keyword search + graph traversal + semantic similarity. Returns ranked memories, profile text, episodes, and abstention flag.

curl -X POST /sessions/s2/retrieve -d '{"user_message":"What does the user prefer?"}'
5

Get Profile

The profile is compiled from active memories into a structured markdown document. GET /profile returns the compiled profile text with all user attributes.

## Profile - user prefers: The user prefers dark mode for all editors. - user drinks: The user drinks coffee every morning.

Key Concepts

Atomic Claims
Each memory is a single, self-contained claim. "The user prefers dark mode." is one memory. "The user likes coffee." is another. This atomicity enables precise retrieval and contradiction detection.
Slot System
Memories have slots (e.g., "home_city", "name", "theme"). Single-valued slots can only have one active memory — a new value supersedes the old one. Multi-valued slots can accumulate multiple memories.
Abstention
When no relevant memories are found, the system returns abstain: true. This prevents hallucination — the LLM should not answer from parametric knowledge.
