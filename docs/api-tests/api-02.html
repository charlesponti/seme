Memories accumulate across separate conversations, building a comprehensive user profile over time.

How It Works

1

Record Turns per Session

Each session is independent — different session_id, different episode. But all memories are stored in the same memory database, linked to the same user identity.

for (let i = 0; i < 5; i++) { await seme.recordTurn(`s${i}`, 'user', `I like language ${i}.`); await seme.endSession(`s${i}`); }
2

Async Extraction per Session

Each session's end triggers an extraction pipeline run. The LLM processes each conversation independently and extracts atomic claims. All memories are stored with the same user_id.

3

Profile Compilation

The profile compiler aggregates all active memories from all sessions into a single structured profile. The profile grows as more memories are added.

4

Cross-Session Retrieval

When retrieving in a new session, the system searches across ALL memories from ALL sessions. The user doesn't need to repeat information from previous conversations.

const ctx = seme.retrieveContext('s5', 'programming'); // Returns memories from sessions 0-4

Key Concepts

Session Independence
Each session has its own episode and turns. But memories are global to the user. This means the system builds a single, unified understanding of the user across all conversations.
Profile Growth
The profile text grows as more memories are added. A user with 5 sessions will have a richer profile than one with 1 session. This is the "accumulation" that makes the system valuable over time.
No Session Silos
The retrieval engine doesn't filter by session. It searches all active memories regardless of which session they came from. This is intentional — the system should "remember" everything the user has ever said.
