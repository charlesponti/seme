API-9

Feedback → Aggregate → Propose → Lock → Verify

The adaptation system: learn from user feedback (compliments, corrections) and propose personality/style changes.

What This Tests

Tests the full adaptation lifecycle: ingest feedback signals, aggregate them into proposals, apply a proposal, and lock the dimension.

How It Works

1

Ingest Feedback

When the user compliments or corrects the assistant, POST /feedback records the signal. Types: compliment_specific, compliment_general, correction, rejection, engagement, disengagement.

await svc.ingestFeedback({ signal_type: 'compliment_specific', target: 'register', detail_json: '{"aspect":"tone"}', episode_id: ep.id });
2

Aggregate

After N feedback signals on the same dimension, POST /adaptations/aggregate analyzes them and proposes changes. Requires minimum signal count.

3

Propose & Apply

Proposals are changes to a dimension (e.g., "register" → "warmer tone"). POST /adaptations/:dimension/apply activates the proposal.

4

Lock

The user can lock a dimension to prevent further automatic changes. POST /adaptations/:dimension/lock with { locked: true }.
