How It Works

1

Entity Name Matching

When the user's query mentions an entity name (e.g., "Charles"), the retrieval engine searches the graph for matching entities by name or alias.

2

Graph Traversal

For each matched entity, the system traverses 2 hops to find related entities and relationships. This provides context beyond the direct match.

3

Graph Summary in Response

The response includes a graph_summary object with matched entities and relationships. This is used by the LLM to provide richer, more connected answers.

{ "graph_summary": { "entities": [{"name": "Charles", "type": "person"}], "relationships": [{"relation_type": "works_at", "source": "Charles", "target": "Ponti Studios"}] } }

Key Concepts

Graph-Augmented Retrieval
The graph is not just for display. During retrieval, the system searches the graph for entities matching the query, then traverses 2 hops to find related context. This is "graph-augmented retrieval" — combining vector/keyword search with graph traversal.
Dual Search
The retrieval engine performs two parallel searches: (1) FTS5 keyword search on memories, and (2) entity name matching on the graph. Results from both are merged and ranked.
