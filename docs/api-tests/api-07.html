How It Works

1

Export All Tables

GET /export dumps all data from all tables: memories, turns, episodes, entities, relationships, profile_versions, identity_core, deletion_log, etc.

2

JSON Bundle

The export is a single JSON object with keys for each table. Each value is an array of rows. This is a portable, human-readable format.

{ "memories": [ { "id": "mem-1", "kind": "fact", "slot": "home_city", "subject": "user", "predicate": "lives in", "value_text": "The user lives in London.", "status": "active", "source_type": "user_stated", "confidence": 0.9 } ], "turns": [ { "id": "turn-1", "session_id": "s1", "role": "user", "content": "I live in London.", "created_at": "2026-10-25T01:40:00Z" } ], "episodes": [ { "id": "ep-1", "session_id": "s1", "started_at": "2026-10-25T01:40:00Z", "ended_at": "2026-10-25T01:40:05Z", "status": "closed" } ], "entities": [ { "id": "ent-1", "name": "London", "type": "place", "aliases": [], "description": "City", "mention_count": 1, "confidence": 0.9, "source_type": "user_stated" } ], "relationships": [], "profile_versions": [ { "version": 1, "status": "active", "rendered_text": "## Profile\n- user lives in: The user lives in London." } ], "identity_core": { "id": "singleton", "rendered_text": "The user is Charles Ponti." }, "deletion_log": [] }
3

Verify

The test checks that memory_count >= 1 and tables_included.length >= 5. This ensures the export is complete and contains the expected data.

Use Cases

Data Portability
Users can export their data and import it into another Seme instance. This is critical for GDPR compliance and user trust.
Backup & Restore
Regular exports serve as backups. If the database is corrupted, the user can restore from an export.
Debugging
Exporting data makes it easy to inspect the full state of the system during development and debugging.
