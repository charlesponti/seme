What This Tests

How It Works

1

Forget All Operation

POST /forget with { target: "all" } deletes all memories. This is a destructive operation that requires confirm: true.

// Without confirmation: await svc.forgetCommand('all', undefined, undefined, undefined, undefined, false); // Throws: ERR_VALIDATION: Confirmation required for delete-all
2

With Confirmation

When confirm: true is passed, all memories are soft-deleted and logged to the deletion_log. This is irreversible (except via restore from backup).

// With confirmation: await svc.forgetCommand('all', undefined, undefined, undefined, undefined, true); // All memories: status = 'deleted' // deletion_log: entries for each deleted memory

Safety Design

Two-Step Confirmation
Destructive operations require explicit confirmation. This prevents accidental data loss from misconfigured API calls or UI bugs.
Soft Delete
Even with confirmation, data is soft-deleted (marked as deleted, not removed). The deletion_log provides an audit trail. Data can be recovered from backups.
Cascade
Deleting all memories also cascades to graph links and profile. The profile is recompiled (empty) and graph entities are unlinked.
