API-11

Invalid Memory ID → ERR_NOT_FOUND

Error handling: when a memory doesn't exist, the system returns a clear ERR_NOT_FOUND error.

What This Tests

Tests that the API returns a proper error (ERR_NOT_FOUND) when requesting a non-existent memory, rather than crashing or returning null.

How It Works

1

Lookup

The system queries the database for the memory ID. If no row is returned, it throws an ERR_NOT_FOUND error with a descriptive message.

try { seme.getMemory('nonexistent-id'); } catch (e) { // e.message === "ERR_NOT_FOUND: Memory not found" }
2

Consistent Error Format

All errors follow the same format: ERR_CODE: descriptive message. This makes it easy for clients to parse and handle errors programmatically.
