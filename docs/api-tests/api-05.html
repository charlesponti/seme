How It Works

1

Remember (Explicit)

The user explicitly tells the system to remember something. POST /remember creates a memory with source_type: user_edited and high confidence. This bypasses the extraction pipeline.

const r = await seme.rememberCommand('s1', 'I live in London.', turnId, 'fact'); // Creates memory: { kind: "fact", slot: "home_city", value_text: "..." }
2

Correct (Edit)

The user corrects a memory. POST /memories/:id/correct creates a NEW memory with the corrected value, marks the old one as superseded, and links them. The new memory has source_type: user_edited.

const corrected = await seme.correctMemory(memId, 'I live in Edinburgh.'); // Old memory: status = 'superseded', superseded_by_id = newId // New memory: status = 'active', supersedes_id = oldId, source_type = 'user_edited'
3

Forget (Soft Delete)

The user deletes a memory. POST /forget soft-deletes (marks as deleted, doesn't remove from DB). Also logs to deletion_log for audit. Cascades to graph links.

await seme.forgetCommand('memory', memId); // Memory: status = 'deleted' // deletion_log: entry created with reason and timestamp
4

Verify

After forget, GET /memories/:id throws ERR_NOT_FOUND. The memory is gone from active queries but preserved in the DB for audit.

Key Concepts

Correction = Supersession
Correcting a memory doesn't modify it in place. It creates a new memory and supersedes the old one. This preserves the history of what the user said vs. what they corrected.
Soft Delete
Forgetting a memory marks it as deleted but doesn't remove it from the database. The deletion_log records who deleted what and when. This supports "undo" and audit requirements.
Source Type Tracking
Each memory tracks its source_type: user_stated (from conversation), user_edited (from explicit remember/correct), inferred (from extraction), feedback_derived (from compliments/corrections). This enables provenance queries.
