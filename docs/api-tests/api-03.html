How It Works

1

Create Entities

Entities are nodes in the knowledge graph. Each has a name, type, aliases, description, source type, and confidence. Types include: person, organization, place, tool, concept, event, preference, habit, goal, skill.

const charles = seme.createEntity('Charles', 'person', [], 'User', 'user_stated', 0.9); const ponti = seme.createEntity('Ponti Studios', 'organization', [], 'Company', 'user_stated', 0.9); const edinburgh = seme.createEntity('Edinburgh', 'place', [], 'City', 'user_stated', 0.9);
2

Create Relationships

Relationships are directed edges between entities. Each has a relation type (works_at, lives_in, uses, etc.), description, source turn/episode, source type, and confidence.

seme.createRelationship(charles, ponti, 'works_at', 'works at', turnId, episodeId); seme.createRelationship(ponti, edinburgh, 'located_in', 'located in', turnId, episodeId);
3

Get Neighborhood (N-hop)

Traverse the graph from an entity up to N hops. Returns all entities and relationships within the neighborhood. Used for "tell me everything about Charles" queries.

const neigh = seme.getNeighborhood(charles, 2);

Find Path

BFS shortest path between two entities. Used for "how is Charles connected to Edinburgh?" queries. Returns the path as an array of entities and relationships.

const path = seme.findPath(charles, edinburgh);

Key Concepts

Provenance
Every entity and relationship is linked to a source turn and episode. This enables "why does the system know this?" queries and supports deletion cascades.
Graph as Retrieval Signal
The graph is not just for display. During retrieval, the system traverses 2 hops from matched entities to find related context. This is "graph-augmented retrieval."
Entity Resolution
When the same entity is mentioned multiple times (e.g., "Ponti Studios" and "Ponti"), the resolver merges them into one entity with multiple aliases.
