The review queue: when the system detects contradictions, it queues them for human review.

What This Tests

Tests the review queue lifecycle: create a review item, list pending items, resolve it (confirm/dismiss/edit), and verify it's removed from the queue.

How It Works

1

Review Item Kinds

Review items are created when the system detects: contradictions (user said X then Y), conflicts (memories disagree), or supersessions (new value replaces old). Each has a kind and payload.

2

List Pending

GET /review-queue returns all pending review items. The UI can display these to the user for resolution.

const items = seme.reviewQueueList();
{
  "items": [
    {
      "id": "ri-1",
      "kind": "contradiction",
      "payload_json": "{\"slot\":\"home_city\"}",
      "memory_ids": "[]",
      "status": "pending",
      "created_at": "2026-10-25T01:40:00Z"
    }
  ],
  "total": 1
}
3

Resolve

POST /review-queue/:id/resolve with action: confirm (keep new), dismiss (keep old), or edit (modify). The item is marked resolved and removed from pending.

const resolved = await seme.resolveReviewItem('ri-1', 'confirm');
{
  "resolved": true
}

When Reviews Are Created

Contradiction Detection
When the user says "I live in London" and later "I live in Edinburgh" without correcting, the system creates a contradiction review item instead of silently superseding.
Sleep Job Conflicts
During the sleep job, when deduplication or contradiction detection finds conflicting memories, review items are created for human resolution.
Graph Entity Conflicts
When the same entity is mentioned with conflicting attributes (e.g., "Ponti Studios" is both a company and a non-profit), a review item is created.
